Public GEO bulk transcriptomics workflow

Before starting, specify the disease or treatment, species, tissue or cell type, target group, reference group, sampling time, outcome, and independent biological unit (for example, a patient, animal, or independent culture). For paired designs, identify the units that form each pair. Mark unresolved details as “unverified.” Use R throughout and call relevant bioSkills when available. Keep R scripts with English comments, processing records, and an English report. Base all results on actual downloads or calculations.

File conventions

Create <GSE>_GEO_bulk_analysis_project for each GEO series. Give each comparison a unique contrast_id and document the target group, reference group, and direction of effect. Replace <P> throughout with <GSE>_<contrast_id>. All paths are relative to the project root. Each matrix has a unique gene_id in the first column and sample_id values as the remaining column headers. Save the gene_id-to-gene_symbol mapping separately. Join sample metadata by sample_id. Include <P> in the names of figures, tables, scripts, reports, and model files. Comparisons from the same GSE may share the original downloads. If a comparison uses multiple cohorts, include the source GSE and sample role in the results.

1. Find datasets, score comparisons, and assign cohort roles

Verify direct access before scoring. Both expression data and per-sample group assignments must be readable or downloadable from a public source without signing in, requesting permission, or contacting the authors. Open the actual file or query the public endpoint and check the file type, sample identifiers, and group fields. For large files, inspect the header or archive listing. In the Excel workbook, record separate links for expression and grouping data (the same link may serve both), the filenames or retrieval methods, and the verification date. Prioritize cohorts with a processed expression matrix or per-sample quantification files. Label cohorts that provide only public FASTQ or CEL files “raw data only; preprocessing required.” Exclude records from the recommended top five if only a publication or GEO landing page is available, files are inaccessible, or direct access remains unverified.

Search for public bulk RNA-seq or expression microarray data suitable for the specified comparison. Start with GEO datasets that provide a sample-level matrix or supplementary processed data. Rank human datasets first and consider mouse datasets when suitable human data are unavailable. Check each GSE, sample table, original study, and download link. Report missing or unconfirmed records accurately.

1.1. Score one comparison from one GSE per row. Verify tissue, sampling time, and outcome, trace each group assignment and independent sample, and locate sample-level expression data or reprocessable raw files. Exclude a comparison when group and batch are completely confounded with no comparable subset, the outcome was never measured, or sample identities cannot be reconciled. Mark unresolved items as “unverified.” Aim for at least three independent biological units per group. Count technical replicates as one unit. Treat groups with fewer than three units as exploratory. For paired studies, count complete pairs.

1.2. Use the following 100-point rubric to prioritize comparisons with similar designs. Assign the highest tier fully supported by evidence. Leave unverified items blank and report both the verified score and the maximum still possible.

- Batch comparability (10 points). Award 10 if all samples share a verified batch or both groups occur in every included batch. Award 5 if some batches include both groups and support estimation of the group effect. Apply the eligibility rule in section 1.1 to complete confounding.
- Key confounders (10 points). List one to three factors relevant to the question. Award 10 if each was controlled by design or was measured with enough overlap between groups for adjustment, 5 if only some can be controlled, and 0 if all are confirmed missing or difficult to control. Exclude a comparison if confounding makes it uninterpretable.
- Effective sample size (15 points). Count independent units in the smaller group or complete pairs. Award 0 points for fewer than 3, 3 for 3–4, 7 for 5–9, 11 for 10–19, and 15 for 20 or more.
- Data usability (15 points). Award 15 for a sample-level matrix suitable for the planned method, with gene annotation and a sample mapping table. Award 10 for per-sample quantification files that require only merging or conversion of known identifiers. Award 5 if raw data require quantification or normalization. Award 0 if the available input cannot support the method and no conversion is possible. Document the limitation.
- Independent validation (25 points). Award 0 if the search finds no candidate or only repeat measurements of the same cohort. Award 8 for indirect support or unverified independence. Award 16 when samples are demonstrably independent and tissue, sampling window, comparison, and outcome match. Award 25 if expression and group assignments are also verified as accessible and each group has at least three independent units. Assess feasibility for predictive modeling separately.
- Contribution beyond existing work (25 points). Award 0 if the analysis only repeats the original question. Award 8 if comparison with the original paper and similar reanalyses identifies a specific new question. Award 16 if the required fields and measurements are also available. Award 25 if the study can additionally specify two explanations the results could distinguish and a prespecified test for doing so.

1.3. Export an Excel workbook with GSE, contrast_id, study population, species, tissue, time, platform, independent sample counts per group, grouping evidence, expression units, matrix and download links, evidence for each score, unresolved items, and preliminary rank. Recommend up to five suitable comparisons. Report the actual count if fewer qualify. Rank using verified points only and finalize the order after checking downloads. Give priority to comparisons with a total of at least 80, scores of at least 16 for both independent validation and contribution beyond existing work, and passing eligibility and quality checks. Retain comparisons scoring 65–79, or higher-scoring comparisons missing a specific requirement, as alternatives. Defer those scoring below 65. Explain each recommendation in terms of the primary comparison, tissue, sample overlap, and workload. Keep visual group separation, the number of significant findings, and AUC out of the ranking.

1.4. Verify data suitability for each shortlisted comparison and assign roles before inspecting differential expression results. Identify discovery/development, independent validation, or alternative cohorts. Check for shared patients, duplicate samples, GEO subseries, and repeated deposits. Document compatibility of outcomes, platforms, and measurable features for external validation. Use each cohort according to its assigned role. Reserve validation cohorts for evaluating results locked during development. Report any unmet independence or compatibility condition.

1.5. For a full analysis, inventory each selected dataset from its sample metadata and original study. List observed tissue or brain region, condition, collection time relative to exposure or withdrawal, and independent units per group. Translate the question into a contrast plan per dataset. For example, a multiregion time course with one baseline calls for each relevant region and each observed time versus its baseline. If the question concerns change between two times or a difference in response across regions, specify a direct contrast or interaction and account for repeated samples from the same individual. Use observed and estimable combinations; the scientific question determines which comparisons are meaningful.

Track planned contrasts in the report or a linked table with dataset, region or tissue, target, reference, independent sample counts, status, and result location or reason for omission. Distinguish a completed comparison with zero significant genes from an unavailable comparison. Check the completed results against this plan before cross-dataset synthesis. A stratum present in only one dataset still contributes to that dataset's findings.

2. Set up the project and download data

In the current directory, create the project and the raw_data, clean_data, scripts, results, and report subdirectories. In an English README.md, explain the project purpose, the <P> naming convention, complete input paths for each comparison, cohort roles, the primary comparison, and its reference group. Download the expression matrix, sample information, applicable platform annotation, and authors’ processing notes. Use GEOquery first. If the Series Matrix lacks sample-level expression, inspect GEO supplementary files. For RNA-seq, also check for NCBI-provided counts for the series and distinguish those from author-provided versions. Confirm the assay type using the sample and platform records. Keep original downloads in raw_data and record the GSE, source URL, retrieval time, method, filename, and path in raw_data/download_log.txt. Report the downloaded files and their purposes before reconciling samples and performing quality control. Save the R download script in scripts.

3. Reconcile sample groups and prepare the data

Verify sample identities before applying group-dependent filters.

3.1. Use GEO sample descriptions, author-supplied tables, and platform records to list original sample names, GSM accessions, and the evidence for each group assignment. Review fields such as title, source_name, and characteristics_ch1 together. Write clean_data/<P>_sample_info.csv with at least sample_id and group. When available, retain patient_id or pair ID, tissue, sampling time, treatment, platform, batch, and study-relevant covariates. Report usable independent units by group and the number of complete pairs. Handle repeated sequencing, multiple sites from the same patient, and repeated time points according to the study design.

3.2. Match the sample table one-to-one with the expression matrix by sample_id and put both in the same order. Correct identifiers only when evidence such as a GEO or author-provided mapping establishes a unique match. Record original and corrected names, supporting evidence, and reasons for exclusion. Exclude duplicate keys, unresolved group assignments, and unverifiable samples from the comparison.

3.3. Identify the expression matrix, metadata, platform annotation, and units. Preserve original identifiers, stable gene_id, gene_symbol, and annotation version. Keep original Ensembl identifiers before removing version suffixes. Document the handling of one-to-many mappings and duplicate identifiers. For microarrays, map probes using the matching GPL. If several reliable probes map to one gene, aggregate their normalized values on the same log2 scale using a prespecified rule such as the mean. Preserve stable identifiers and the count scale of raw RNA-seq gene counts.

3.4. For RNA-seq with raw gene counts, save clean_data/<P>_counts.csv for DESeq2 or edgeR. Where suitable transcript-level quantifications are available, use the appropriate import workflow and retain the counts and required adjustment terms. Separately save an expression matrix suitable for exploratory plots and WGCNA, such as variance-stabilized values or appropriately normalized logCPM, in clean_data/<P>_clean_expression_matrix.csv. For arrays, use the same filename for the gene-level matrix after verifying the platform, normalization, and log2 scale. If only TPM or FPKM values are available, look for usable counts. If none are available, document the limitation and choose methods compatible with the units and their comparability across samples. Never round TPM, FPKM, or transformed values to generate raw counts.

3.5. Prespecify platform-appropriate filters for low expression, missingness, and ambiguous annotation. Record dimensions before and after filtering, annotation coverage, usable sample counts per group, expression distributions, sample clustering/PCA, and batch information. Cross-tabulate group and batch. Exclude an outlier only with supporting data-quality evidence. Preserve the processing history in the report and sample records. In the README, document each matrix’s units, transformation, gene identifiers, and permitted uses. For prediction performance estimates, start with raw inputs or inputs that can also be prepared for new samples, then apply the training-only rules in section 10.

4. Differential expression (results/DEG)

Use applicable bioSkills to compare the prespecified target and reference groups in verified samples. Use DESeq2 or edgeR for RNA-seq counts and limma for appropriately normalized array expression. Account for pairing, estimable batch effects, and prespecified confounders. Check that the design matrix supports estimation of the contrast. Positive log2FoldChange indicates higher expression in the target group.

Use BH-adjusted P value (padj) < 0.05 by default. Choose the primary fold-change rule before inspecting results, using the biological question and the smallest change of interest. For example, |log2FoldChange| > 1 selects changes greater than twofold in either direction. When smaller changes are relevant, the cutoff may be relaxed to 1.5-fold or 1.2-fold (absolute log2 cutoffs of log2(1.5) or log2(1.2)), or the primary analysis may use the FDR criterion alone. Record the cutoff and its rationale. If a cutoff is relaxed after inspecting the results, retain the original primary analysis and label the additional results as exploratory sensitivity analyses.

Write results/DEG/<P>_DEG_all.csv with all tested genes, gene_id, gene_symbol, log2FoldChange, test statistic, P value, and padj. Flag untestable entries. Write results/DEG/<P>_DEG_significant.csv using the declared primary rule. Report the number of genes passing FDR alone and, whenever an effect-size cutoff is used, the number meeting both criteria. Keep sensitivity lists separate and identify the rule used for any downstream enrichment or candidate selection. If no genes qualify, write the corresponding table with headers and zero rows and retain the full table for GSEA. Produce a volcano plot and, when suitable genes are available, a heatmap. Export high-resolution PNG and PDF figures. Report the design, parameters, and observed results.

5. GO and KEGG enrichment (results/Enrich)

Use clusterProfiler with the correct species to test genes from results/DEG/<P>_DEG_significant.csv for overrepresentation in GO Biological Process (BP), Cellular Component (CC), Molecular Function (MF), and KEGG. For each database, define the background as tested genes eligible for the significant list that mapped to that database. Obtain these from results/DEG/<P>_DEG_all.csv and the testing/filtering records. Report gene_id conversions, foreground and background counts, database versions, and losses during mapping. If the foreground is empty, record the reason and skip this branch.

In results/Enrich, export <P>_GO_BP.csv, <P>_GO_CC.csv, <P>_GO_MF.csv, and <P>_KEGG.csv. Retain all available results and flag terms with BH padj < 0.05. Make a dot plot for each category showing up to ten significant terms, using the actual number that qualify. Explain how the principal terms may relate to the study question.

6. Preranked GSEA (results/GSEA)

Read results/DEG/<P>_DEG_all.csv independently of the significant-gene list. Rank all tested and mappable genes with finite ranking scores by the prespecified log2FoldChange in descending order. Use one entry per gene identifier and document how duplicates, ties, and missing values were handled. Use the appropriate species-specific MSigDB Hallmark collection. Record its version, identifier type, collection category, and any required cross-species mapping. This analysis can proceed with an empty significant DEG table.

Save results/GSEA/<P>_GSEA_result.csv with gene set name, normalized enrichment score (NES), P value, padj, and significance flag. Use BH padj < 0.05. Report up to five significant sets enriched at the target-group end of the ranking and up to five at the reference-group end. For the overview dot plot and running enrichment score plots, use the five most significant sets overall or the actual number available. Explain enrichment direction in English in terms of the relative expression ranking. Biochemical activation or inhibition requires additional evidence.

7. Weighted gene co-expression network analysis (results/WGCNA)

Read clean_data/<P>_clean_expression_matrix.csv and clean_data/<P>_sample_info.csv. Build the network from a quality-controlled expression matrix suitable for correlation analysis, independently of the DEG list and enrichment results. Verify the number of genuinely independent samples in this comparison. Skip network construction below 15 and prefer at least 20 where possible. For repeated measurements, justify the sample selection or handling and report the decision.

7.1. Among eligible samples, select up to 5000 usable, nonconstant genes by descending median absolute deviation (MAD). Record the threshold and actual count. Plot the sample dendrogram, apply the quality-control rules to verified technical anomalies, and update sample counts by group.

7.2. Plot scale-free topology fit and mean connectivity for candidate soft-threshold powers (β). With reasonable connectivity, use the first power at which R² reaches 0.85 as a reference. If none reaches the target, inspect batch effects, outliers, and sample structure. Record and justify an alternative β using WGCNA methodology, or stop this branch if the data cannot support a reliable network.

7.3. Construct the network in one step. Record the network type, minimum module size (for example, 30 genes), and merge threshold (for example, 0.25). Plot the gene dendrogram with a module color bar. Report the number of modules and the size of each.

7.4. Test module eigengene (ME) associations with the trait under the defined contrast and coding. Account for pairing or covariates as appropriate. Report the direction, correlation or adjusted effect, P value, and BH adjustment across tested modules. Draw a module–trait heatmap. Prespecify how to select the primary module. One rule is to take the largest absolute association among non-grey modules with padj < 0.05, report its sign, and use a predetermined order to break ties. If none qualifies, report “no significantly associated module.”

7.5. If a module qualifies, plot gene significance (GS) against module membership (MM) and export results/WGCNA/<P>_WGCNA_hubmodule_genes.csv with gene_id, gene_symbol, module name, GS, and MM. This table lists members of the selected module. The filename alone does not establish that a member is a hub. If no module qualifies, record the status or export an empty table with headers.

8. Intersect candidate gene lists (results/HubGene)

Read results/DEG/<P>_DEG_significant.csv and results/WGCNA/<P>_WGCNA_hubmodule_genes.csv. Confirm the same species and stable gene_id namespace, remove duplicates, and intersect the lists. Keep gene symbols as labels. Export results/HubGene/<P>_candidate_genes.csv, draw a Venn diagram, and report counts for significant DEGs, module members, and their intersection. The candidates meet both selection criteria in this discovery cohort. If an upstream branch could not run successfully, record “selection unavailable” and the reason. If both inputs are valid but have no genes in common, write an empty table. If the candidate list is empty or unavailable, record the status for STRING and proceed to the expression-based fallback in section 10.

9. Visualize the STRING protein network (results/PPI)

Read results/HubGene/<P>_candidate_genes.csv. Set the taxon ID to match the dataset (9606 for human, 10090 for mouse). Use STRINGdb with score_threshold = 400 for a confidence threshold of 0.4. Include candidate protein nodes only and add no extra nodes. Record the STRING and software versions, query date, evidence channels, and network type. Interpret a functional association network in terms of functional associations. Export the gene-to-protein mapping, unmapped genes, and mapped isolated nodes.

Draw a legible force-directed network with node size proportional to degree, color distinguishing connected from isolated nodes, and edge width indicating confidence. Avoid overlapping labels. If the network has no edges, report its actual size and mapping results. Use PPI for visualization. STRING mapping and connectivity do not determine which expression features can enter machine learning.

10. Select features by machine learning (results/ML)

For a full analysis, run LASSO, random forest, and SVM-RFE for each planned binary contrast with observed group labels and usable expression. Use the target and reference in clean_data/<P>_sample_info.csv and name the measured outcome in the report (for example, diagnosis or treatment stage). A cohort used for descriptive cross-dataset comparison can also support its own labeled classification task. Keep a cohort explicitly reserved for independent validation held out for the frozen model.

Set the feature rule before resampling. By default, use the DEG–module intersection computed in the training data when available. Otherwise use measurable expression features that vary in the training data. If dimension reduction is needed, prespecify the number retained and rank by variance within training data. Apply the same rule in every training split and the final fit, record which input was used, and carry selected features into the corresponding test set. Save the random seed, software versions, sample splits, and label coding.

Use internal validation when no compatible external cohort is available. For external validation, apply the feature rule and tune on the full development cohort, then evaluate the frozen model on compatible independent samples.

For an internal performance estimate of the entire modeling procedure, first split independent patients or biological units into outer training and test sets. Within each outer training set, learn the preprocessing, apply the specified feature rule, select features with the three methods, and fit the models. Within each inner training fold used for tuning, also learn features and preprocessing only from that fold. Keep all specimens from a patient together in every split. Use each outer test set only for scoring. Do not reuse candidates or fitted preprocessing parameters from the full development set in internal testing. If using a bootstrap estimate of optimism for the full procedure, repeat all selection and fitting steps in each patient-level resample. Prespecify how to handle and report insufficient samples, single-class splits, or empty selection. Retain failure counts and report all folds.

10.1. Use stratified fivefold cross-validation when feasible. Choose a feasible fold count based on the independent units available in each class and the training size per fold. If any training or evaluation stage lacks a valid two-class comparison, reduce the number of folds according to a prespecified rule or report that performance cannot be estimated. Assess modeling feasibility separately from the minimum sample size for differential expression.

10.2. For binary LASSO, select lambda by cross-validation within training data. Lock the selection rule before fitting, for example, nonzero coefficients at lambda.1se. Draw cross-validation and coefficient-path plots and export the selected genes and coefficients. For SVM-RFE, perform recursive elimination and tuning within training data. Prespecify candidate feature counts and the tie-breaking rule, such as taking the smaller set at equal error. Export feature rankings, selected genes, and the error-rate curve.

10.3. Tune random forest parameters by cross-validation. Prespecify the variable importance measure and selection rule. For example, rank by permutation importance and retain up to K genes with positive importance, setting K before inspecting test performance. Export the importance table, selected genes, and ranked importance plot. If parameter values are initially uncertain, write down a reproducible rule before training.

10.4. Summarize selections from all three methods on the development set, draw a Venn or UpSet plot, and export their intersection to results/ML/<P>_consensus_genes.csv with at least gene_id and gene_symbol. Report each method's held-out performance when estimable, its selection count, the intersection, and missingness. Retain the individual methods' results when their consensus is empty. If no genes are shared by all three methods, export a header-only table and skip the gene nomogram that depends on it. Export tables as CSV and figures as PDF. Save model objects, seeds, fold assignments, and sessionInfo().

11. Build and validate the nomogram (results/Nomogram)

11.1. Read results/ML/<P>_consensus_genes.csv, gene expression on the same scale, and clean_data/<P>_sample_info.csv. Align by sample_id and gene_id. Check missingness, outliers, variable types, collinearity, and the functional form of continuous variables. Assess fitting feasibility from the number of development samples, class or event counts, and the number of candidate parameters. If prespecified clinical variables such as age are included, compare the clinical-only and combined clinical-plus-gene models using the same participants and validation plan.

11.2. For binary group outcomes, fit logistic regression with rms::lrm() and draw the medical nomogram with rms::nomogram(). If the original question specifies a survival outcome, use a Cox model such as rms::cph() only when follow-up times, event status, prediction horizons, and prespecified features suited to that outcome are available. Check the proportional hazards assumption. Feature selection for the binary outcome does not establish eligibility for a survival model.

11.3. Export the formula, coefficients, standard errors, P values, odds or hazard ratios, and 95% confidence intervals. State the limitations on inference after data-driven selection. For internal validation, use full-procedure bootstrap estimates or outer holdout predictions from section 10. Report estimates and uncertainty. As supported by the outcome and data, evaluate ROC-AUC or the C-index, calibration curves, and decision curve analysis (DCA). With fixed case/control sampling quotas, fitted probabilities reflect the sampling proportions. Target-population absolute risk and DCA net benefit require target prevalence or an appropriate sampling adjustment. Without that basis, report the supported classification scores and discrimination.

11.4. After development, freeze the model formula, genes, normalization and transformations, missing-value rules, coefficients including the intercept, and any classification threshold. For a designated independent validation cohort, verify that participants do not overlap, phenotypes match, key genes are measurable, and inputs can be put on the required scale using the frozen procedure. Apply the same model to each sample and summarize external results. Reselecting genes, fitting preprocessing parameters, or choosing a threshold on validation data precludes external validation of the frozen model. If external validation cannot be performed, give the reason and distinguish internally validated from apparent performance.

11.5. Export results/Nomogram/<P>_model_predictions.csv. Include sample_id, source GSE, cohort role, prediction type (development fitted value, outer holdout, or external validation), observed outcome, and predicted probability or risk score. Identify the population to which any probability applies. Save model objects, the nomogram, validation figures, plotting data, code, and full parameter records.

12. Synthesize results across datasets

For each proposed link, name the source contrasts and check species, tissue or anatomical correspondence, exposure, timing, outcome, effect direction, and participant overlap. Compare independent cohorts measuring the same effect using effect estimates, uncertainty, and direction for shared measurable genes. Pool estimates only when the designs and effect scales support a common interpretation. Account for shared controls or repeated participants where applicable.

For different species, platforms, or related but distinct outcomes, document the gene mapping and number of comparable genes or pathways. For one-to-one ortholog analyses, establish uniqueness in the reference mapping before restricting to measured genes. Compare aligned effect directions or ranked pathway results and show discordant findings as well as agreement. State which links are descriptive, which qualify as independent replication, and which strata have no counterpart. Limit causal claims to relationships the study designs can test.

Deliverables

Save reproducible R scripts for each comparison and stage in scripts, with English comments. Save analysis tables and figures in the appropriate results subdirectories, and English processing records and the overall report in report. Use legible publication-style figures for differential expression, GO/KEGG, GSEA, WGCNA, Venn diagrams, and PPI. Export these as PDF and high-resolution PNG. Use a muted Morandi palette for enrichment, WGCNA, and Venn diagrams. Record the actual inputs, inclusion and exclusion decisions, units, groups and contrast direction, parameters, versions, seeds, sample and gene counts at each step, and reasons for empty results.
